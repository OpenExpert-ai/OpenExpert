# 05 · Artificial intelligence

> **Audience:** both. Tools, isolation and limits.

---

## 1. Model and provider

The model is configuration (see [AI providers](./13-ai-providers.md)): `ollama`
(local), `google` (Gemini free key), `anthropic` (Claude), `openai-compatible`
(BYOK) or `opencode-go`. Each provider keeps **its own** key, in its own
variable, and changing provider does not erase the previous one. The assistant
always answers in Spanish, shows its reasoning and streams token by token (up to
50 steps per turn).

A step has a hard deadline (4 minutes, `OPENEXPERT_CHAT_TIMEOUT_MS` to change it).
Node's `fetch` has no request timeout of its own, so a provider that accepts the
connection and never answers used to leave the turn streaming until the user
pressed Stop. The deadline also covers the tools of that step, so it outlasts the
slowest one (`run_python` runs up to 120 s), and when it expires the turn ends
with a message that says what happened instead of stopping in silence. The
activity log files that turn as `failed` and names the deadline in the summary
(only a turn that answers is filed as `ok`), and the empty assistant message is
not stored: a turn without a reply leaves no bubble in the history.

## 2. Tool catalog

The assistant has no direct database access; it can only call these tools.

### Read

| Tool                       | Content                                                            | Domain      |
| -------------------------- | ------------------------------------------------------------------ | ----------- |
| `get_pipeline_summary`     | Open value, deal count, win rate, weighted forecast, stalled deals | `ventas`    |
| `list_deals`               | Open opportunities, optionally by stage                            | `ventas`    |
| `list_overdue_invoices`    | Overdue invoices with amount, days overdue, logged reminders       | `finanzas`  |
| `get_campaign_performance` | Spend, conversions, real CPA vs target, status                     | `marketing` |
| `get_churn_risk`           | MRR, usage trend, open tickets, churn probability                  | `clientes`  |

Business data is **not shipped**: the tables start empty. A tool only claims a
vendor as its source when that integration is connected (`connected: true`);
otherwise it returns a `note` saying there is no connected source, so the
assistant never presents local data as real.

The days an invoice has been late are counted on the calendar, in the local
timezone: the day the invoice falls due and the day it is read are compared as
days, so the hour of the day never adds a day to the count. The same number is
the one the collection-reminder card shows, because both come from the same
query.

### Capabilities (off by default)

| Tool         | Function                                                      | Enable                            |
| ------------ | ------------------------------------------------------------- | --------------------------------- |
| `run_python` | Calculations, run as a short Python script (standard library) | `python` in `sources`, per Expert |

The script runs in a private temporary directory, with a scrubbed environment, a
hard timeout (30 s, up to 120 s) and capped output, and the script itself is
written to the activity trail. The network is always cut off: it runs inside a
network namespace of its own, and when the system cannot create one the script is
not run at all. The rest of the disk is out of reach only under `bubblewrap` —a
read-only `/usr` and the working directory—, so without it the script does not run
either: `unshare -Urn` isolates the network and leaves your keys readable, which
is worse than not running anything, and the refusal says how to install it. The
interpreter has to be the system one, under `/usr`, `/opt`, `/lib` or `/lib64`,
because those are the directories the sandbox mounts.

| --------------------------- | --------------------------------- |

## 3. Per-domain isolation

Each read tool belongs to a domain. Every Expert stores the domains it may read
in `experts.domains`; the server checks the domain against that list before
returning data, otherwise it returns an explicit "out of context" error, not
data. Drive access is decided by the Expert's `sources`; local folder access is
decided by the `local` source and is further restricted to the granted folders.
Domains are chosen when creating or editing an Expert; an Expert with no domains
can still chat and use the sources, but reads no business data.

## 4. Limits

| Limit             | Value                                                                               |
| ----------------- | ----------------------------------------------------------------------------------- |
| Steps per turn    | 50                                                                                  |
| History retention | Configurable (`chat.retentionDays`), 30 days for every Expert; `0` disables pruning |
| Cost              | Provider's; Ollama is free                                                          |
