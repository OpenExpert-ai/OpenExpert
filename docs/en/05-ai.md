# 05 · Artificial intelligence

> **Audience:** both. Tools, isolation and limits.

---

## 1. Model and provider

The model is configuration (see [AI providers](./13-ai-providers.md)):
`ollama` (default, local), `google` (Gemini free key) or `openai-compatible`
(BYOK). The assistant always answers in Spanish, shows its reasoning and streams
token by token (up to 50 steps per turn).

## 2. Tool catalog

The assistant has no direct database access; it can only call these tools.

### Read

| Tool                       | Content                                                            | Domain           |
| -------------------------- | ------------------------------------------------------------------ | ---------------- |
| `get_pipeline_summary`     | Open value, deal count, win rate, weighted forecast, stalled deals | `ventas`         |
| `list_deals`               | Open opportunities, optionally by stage                            | `ventas`         |
| `list_overdue_invoices`    | Overdue invoices with amount, days overdue, reminders              | `finanzas`       |
| `get_campaign_performance` | Spend, conversions, real CPA vs target, status                     | `marketing`      |
| `get_churn_risk`           | MRR, usage trend, open tickets, churn probability                  | `general`        |
| `list_processes`           | Process catalogue (only the Expert's domains)                      | Expert's domains |

Business data is **not shipped**: the tables start empty. A tool only claims a
vendor as its source when that integration is connected (`connected: true`);
otherwise it returns a `note` saying there is no connected source, so the
assistant never presents local data as real.

### Google Drive (optional)

| Tool                | Requires              |
| ------------------- | --------------------- |
| `search_drive`      | `gdrive` in `sources` |
| `read_drive_file`   | `gdrive` in `sources` |
| `create_drive_file` | `gdrive` in `sources` |
| `update_drive_file` | `gdrive` in `sources` |

### Local files (optional)

| Tool                                      | Requires                              |
| ----------------------------------------- | ------------------------------------- |
| `list_local_files` / `search_local_files` | `local` in `sources`                  |
| `read_local_file`                         | `local` in `sources`                  |
| `create_local_file` / `update_local_file` | `local` in `sources` + human approval |

Read tools extract text from plain text, PDF, Word (`.docx`), Excel (`.xlsx`)
and PowerPoint (`.pptx`) files, for both local folders and Google Drive.

### Proposals (do not execute)

| Tool                        | Proposes                          |
| --------------------------- | --------------------------------- |
| `propose_invoice_reminders` | Send collection reminders         |
| `propose_pause_campaigns`   | Pause campaigns over their target |
| `request_process_run`       | Run an autonomous process         |

These create an `activity` row with status `pending`, shown as a confirmation
card. Nothing changes until you approve it.

### Utility

| Tool               | Function                    |
| ------------------ | --------------------------- |
| `open_expert_form` | Form to create a new Expert |

## 3. Per-domain isolation

Each read tool belongs to a domain. Every Expert stores the domains it may read
in `experts.domains`; the server checks the domain against that list before
returning data, otherwise it returns an explicit "out of context" error, not
data. `list_processes` and `request_process_run` respect the same list, so a
process is only visible and runnable from an Expert that owns its domain. Drive
access is decided by the Expert's `sources`; local folder access is decided by
the `local` source and is further restricted to the granted folders. Domains are
chosen when creating or editing an Expert; an Expert with no domains can still
chat and use Drive, but reads no business data.
